# GitHub-only runtime audit

**Verdict: fails the GitHub-only requirement.** A fresh Linux Electron profile downloaded a Chromium spellcheck dictionary from Google's CDN. Separately, a controlled backend checkout reached a proxy specified in Git configuration. Normal PR reads worked, but neither the backend fetch guard nor Electron's session filter is a process-wide network boundary.

## Runtime evidence

Tested the local `github-only-runtime` changes on upstream base `0db2ead` using the pinned Nix shell (Bun 1.4.4, Electron 45.3.4). The backend, desktop profile, and mirror/worktree were fresh scratch resources on an unused loopback port. The run used an existing personal credential and one public repository, `theolundqvist/pr-cockpit` (PR #74). Repository discovery was skipped by preseeding that repo, to avoid fetching an account-wide repo list. The running Cockpit instance was left alone. No GitHub writes, login changes, or scope changes were made.

Followed backend, Electron, and CLI descendants with `strace -f` from process creation, recording socket destinations and process execution without payloads or arguments. Correlated Electron's sockets with Chromium NetLog and backend IPs with GitHub's published ranges, DNS answers, and the operations exercised. Electron ran with the Chromium sandbox enabled. The backend was observed for 70 seconds after becoming healthy, and Electron for about 14 seconds from launch through shutdown.

| Path | Observed result |
| --- | --- |
| Backend and children | External application sockets went to GitHub API/Git and GitHub's content CDN on port 443. Local Unix-socket lookups used the system name-service stack; upstream traffic from that stack was not traced. Auth was ready with `repo`. PR detail, Actions list/graph requests, a scratch mirror checkout, and a raw GitHub image succeeded. The first diff request returned `503 {"building":true}`; the rendered Files tab and subsequent CLI diff succeeded. The fixture had no stored Actions runs to exercise log downloads or graph parsing. |
| Electron and children | Cockpit and its WebSocket used the scratch loopback origin. A direct session fetch to `avatars.githubusercontent.com` returned `200`. Separately, Chromium requested `redirector.gvt1.com/edgedl/chrome/dict/en-us-10-2.bdic`; NetLog showed `302` to a `*.gvt1.com` CDN endpoint, `200`, and response-body reads. This was an actual non-GitHub transfer, not just a DNS lookup. Three IPv6 UDP connect probes to Google's public resolver address on port 443 failed with `ENETUNREACH`; no DNS exchange was established by those probes. |
| CLI read | The public PR diff succeeded. The CLI process tree opened only the scratch backend's loopback address. |
| Request-level negative controls | Electron rejected a fetch to a second loopback origin; the backend image proxy returned `400` for the same disallowed origin. The canary received no requests in the default run. Relay coverage, cloud-model discovery, and the update API returned `403`. |
| Git proxy control | A separate scratch backend used a temporary `[http "https://github.com/"]` proxy setting pointing at the canary. The PR detail returned `200`; scratch checkout triggered the Git HTTPS helper, whose loopback connection delivered `CONNECT github.com:443` to the canary. The canary refused the tunnel and checkout returned `502`. The user's Git config was not changed. |

Seven focused fetch-policy and renderer link tests passed. They cover off-GitHub redirects, cross-origin credential stripping, and a mocked review-write redirect; no live review mutation was tested. The trace is an observation, not an enforcement test or a long-running soak. It does not cover the full default poll interval, macOS, Actions log downloads, legacy managed launches, or traffic delegated to an already-running system service or external app.

## Source findings and fixes needed

1. **Chromium networking bypasses request interception.** [`shell/main.js`](../shell/main.js) blocks disallowed Electron session requests and sets `disable-background-networking`, but the built-in dictionary download bypassed both. Disable automatic spellcheck downloads before creating any windows or sessions (or supply dictionaries locally), then retest with a fresh profile and locale.
2. **Native Git inherits configuration.** [`server/mirror.ts`](../server/mirror.ts) sets a GitHub HTTPS remote, disables redirects, resets the credential helper, and sets `http.proxy=`. As the control showed, the URL-specific proxy setting still wins. Checkout and branch-switch operations can also inherit hooks and filters; those were identified in source, not exercised as network paths. Isolate Git transport configuration and constrain hooks, filters, and subprocess environment for app-owned operations.
3. **Legacy entry points and handoffs are not covered by the guards.** The supported Nix `scripts/dev` flow separates setup from normal launches. The old [`scripts/cockpit`](../scripts/cockpit) can invoke startup recovery, and [`scripts/update-pull`](../scripts/update-pull) fetches the configured `origin`. The legacy CLI still offers SSH replica mode and a macOS bootstrap fallback. External browser and editor handoffs leave the guarded application context. Retire or explicitly exclude these paths before claiming a supported GitHub-only runtime.
4. **Enforce egress independently of the app.** [`server/githubNetwork.ts`](../server/githubNetwork.ts) validates Bun fetch destinations and redirect hops; it does not mediate arbitrary native sockets or subprocesses. For a strict guarantee, add a fail-closed OS/broker policy over the complete process tree, with explicit exceptions for local UI traffic and necessary DNS resolution. Re-run the workflow and negative controls under that policy, recording both attempted and permitted egress. Do not solve Actions or private attachment failures by allowing generic external storage.

## Separate issue: workflow graphs

The reported dynamic Copilot workflow path is `dynamic/agents/copilot-pull-request-reviewer`. [`server/runLogs.ts`](../server/runLogs.ts) tries to read the stored workflow path as source at the run's head commit. The warning arose on the local source lookup path, which degrades to `Workflow definition unavailable`; it is not evidence that the network policy denied a request. The identifier may represent a generated workflow with no checked-in YAML at that path. That was not verified against the private commits. The separate `uses the personal token: viewer` message refers to the viewer credential rather than a GitHub App credential, not to an off-GitHub destination or necessarily the user's personal account.
